# 药脉（pharma-radar）设计文档

> 日期：2026-11-03
> 状态：设计已确认，待评审
> 一句话：每天 19:00 自动抓取、按投资与咨询口径过滤医药行业信息，沉淀成一个可长期积累的行业认知网页。

---

## 1. 背景与目标

使用者正在转入 MSL（医学科学联络官）方向，处于长期求职待机期，需要一条不依赖意志力的持续输入通道：每天花 10 分钟，保持对整个医药行业的判断力，面试时能随时调动。

**目标**

1. 每天 19:00 自动生成当日行业信息页，10 分钟可读完
2. 按投资与咨询口径筛选，只保留能改变判断的信息
3. 长期沉淀为一张「认知地图」——六个月后能回答「我懂不懂这个行业」
4. 为面试提供可即时调用的「领域档案」

**非目标**

- 不做实时行情、不做个股评级、不做预测
- 不做社交或协作功能
- 不做公司定向监控（不锁定特定雇主）
- 不做付费数据源接入

---

## 2. 核心判断：用覆盖度替代相关性

不锁定目标公司之后，「这条跟我多近」失效。全面认识一个行业，真正的失败模式不是漏掉某条新闻，而是**信息流塌进单一话题**（例如被肿瘤 BD 新闻霸榜）。

因此本系统的筛选机制由两部分组成：

- **纵向**：材料性打分（M，1–5），决定一条消息值不值得进
- **横向**：六维覆盖配额，决定版面不被单一话题吃掉

---

## 3. 纳入标准

一条消息必须同时通过三问，才进入系统：

1. **新信息** — 跨源聚类去重后仍有新增内容
2. **改变预期** — 能说出一句「之前以为 X，现在认为 Y」
3. **可讲述** — 能用于认知积累或面试表达

未通过第 2 问的，即使金额大、公司有名，也不收。预期差优先于绝对规模。

---

## 4. 材料性评分 M

M 衡量的是「这条在多深的地方改变了通行认知」，与公司名气、金额大小不直接挂钩。

| 分 | 定义 | 示例 |
|---|---|---|
| 5 | 改变某个疾病领域或技术路线的通行认知 | class-level 读出、指南改写、首个 FIC 获批、重大 class effect 安全性争议、集采/医保规则本身的改变 |
| 4 | 明确的方向性变化 | 单品种关键 III 期读出、新适应症获批、重要指导原则发布、医保目录结果、1–5 亿美元级 BD |
| 3 | 值得知道 | III 期启动、IND/NDA 受理、早期阳性数据、常规指南更新、组织与人事变动 |
| 2 | 常规 | 例行 IND、会议摘要、例行财报项 |
| 1 | 噪音 | 公关稿、无数据的「战略合作」、股吧内容 |

评分只看两件事：**预期差**（市场原本的共识 vs 现在的信息）与**波及面**（影响一个品种 / 一条技术路线 / 行业规则）。

早期规则实现：事件类型 + 关键词 + 金额区间 → 基础分；模型只修正边界案例。规则先行是为了避免模型把所有公关稿说成大事。

---

## 5. 六维覆盖

每条消息打**一个主维度**。

| 维度 | 收什么 |
|---|---|
| D1 疾病领域与治疗格局 | 指南与专家共识、标准治疗变迁、未满足需求、流行病学、患者组织 |
| D2 临床开发 | 试验设计与终点、数据读出、失败与提前终止、头对头、真实世界研究 |
| D3 监管与审评 | 受理与获批、附条件批准、突破性疗法、优先审评、指导原则 |
| D4 准入与支付 | 医保谈判、集采、定价、DRG/DIP、双通道、药物经济学 |
| D5 商业与竞争 | 上市表现、BD 与并购、出海、管线优先级调整、组织变动 |
| D6 行业生态 | 合规规范、医学事务岗位与人才流动、平台技术（ADC/双抗/细胞治疗/小核酸/GLP-1/PROTAC/AIDD）、政策环境 |

**冲突规则**：技术的临床意义归 D1，技术路线的商业与人才意义归 D6；无法判定时进 D6。

**配额**

- 每日上限 20 条
- 单维度每日最多 5 条，超出按 M 降序截断
- D1–D5 每日各至少 1 条
- D6 每周至少 5 条
- 周末统计：某维度连续两周低于配额，下周提高该维度来源权重

---

## 6. 数据模型

每条消息一个 Item，字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | URL 规范化后的 hash，幂等合并用 |
| `date` | date | 事件日期（缺失时取抓取日期） |
| `published_at` | datetime | 源发布时间 |
| `source` | string | 来源标识 |
| `source_weight` | number | 来源可信度权重，用于同 M 排序 |
| `lang` | enum | zh / en |
| `title` | string | 原文标题 |
| `title_zh` | string | 中文转写（英文源必填，≤30 字） |
| `url` | string | 原文链接 |
| `company` | string[] | 涉及公司 |
| `drug` | string[] | 涉及药品/代号 |
| `target` | string[] | 靶点 |
| `ta` | string[] | 治疗领域 |
| `event_type` | enum | 交易并购 / 临床结果 / 监管审批 / 准入支付 / 商业组织 / 科学与机制 / 合规政策 |
| `dimension` | enum | D1–D6，主维度 |
| `m` | integer | 材料性 1–5 |
| `why` | string | ≤40 字，行业口径：这条为什么重要 |
| `cluster_id` | string | 同一事件的多源报道归入同一 cluster |

存储：`data/YYYY-MM.jsonl`，按月分文件，只追加不修改。构建时合并为 `public/items.json`。

**日报期与事件日（2026-11-03 补充）**：`published_at` 保存源发布的真实时刻，是判断「什么时候发生」的唯一依据。`date` 用于日报归档：凡进入本期窗口（前一日 19:00 至当日 19:00）的条目，`date` 记为本期日期；源没有发布时间时，`date` 取抓取日期。这样跨夜的欧美消息出现在当晚的「今日」页，而不是被推到前一天的版面。后续若需要事件时间轴（催化剂日历、领域档案时间线），用 `published_at`，不要用 `date`。

**催化剂条目**独立存储 `data/catalysts.json`，字段：`date`、`kind`（读出/审批决定/会议/政策窗口）、`entity`、`drug`、`note`、`source`。

## 7. 架构

```
sources/*.py            每个源一个适配器，输出统一 Item
  ├─ rss_en.py          Endpoints / Fierce / STAT / BioPharmaDive / Nature Biotech
  ├─ reg_cn.py          NMPA 公告、CDE 受理与指导原则
  ├─ trials.py          ClinicalTrials.gov / 中国药物临床试验登记平台
  ├─ openfda.py         openFDA 获批、标签、FAERS 信号
  ├─ media_cn.py        中文医药媒体（静态页面 + 本机代理；pyrecrawl 仅作人工补抓）
  └─ filings.py         港交所 + A 股公告
        ↓
filter.py               去重 → 跨源聚类 → 规则打分 → 维度分配 → 配额截断
        ↓
data/YYYY-MM.jsonl      data/catalysts.json
        ↓
build.py                → public/items.json
        ↓
GitHub Pages            纯静态 HTML/CSS/JS
```

**首批源清单**

| 适配器 | 源 | 语言 |
|---|---|---|
| `rss_en.py` | Endpoints News、Fierce Biotech / Fierce Pharma、STAT、BioPharma Dive、Nature Biotechnology | en |
| `reg_cn.py` | NMPA 药品公告、CDE 受理与指导原则发布 | zh |
| `filings.py` | 港交所披露易、上交所/深交所公告（医药板块） | zh |
| `media_cn.py` | 生物谷、药智新闻、药时代 | zh |

源可增删，适配器接口不变。新增源只需实现「取回 + 归一化为 Item」。

**决定（2026-11-04，取代上表的初版源清单）**：pyrecrawl 只提供 MCP stdio 服务，没有 HTTP/CLI/库接口，`run.py` 无法直接调用它；它改为人工补抓 JS 渲染站点的工具，不进入自动流水线。`media_cn.py` 因此只接能静态取回的中文源，经 `requests` 走本机代理 `127.0.0.1:7890`（可用环境变量 `PHARMA_RADAR_PROXY` 覆盖，设为空串即不走代理，供 GitHub Actions 使用）。

实测可达并在本期接入的三个源：

| 源 | 入口 | 可解析内容 |
|---|---|---|
| 生物谷 | `https://news.bioon.com/1.html`（分页最新列表） | 标题、日期 |
| 药智新闻 | `https://news.yaozh.com/`（首页头条区） | 标题、日期 |
| 药时代 | `https://www.drugtimes.cn/`（首页） | 标题、URL 内含发布日期 |

初版清单里的医药魔方、界面新闻医药、第一财经医药、36 氪医疗实测均为 JS 渲染或反爬（36 氪 `/feed` 返回反爬页面，多个频道页无文章链接），本期不接；需要时用 pyrecrawl 手动补抓，或改为浏览器渲染后再接入。

### 付费数据库的边界

智慧芽（PatSnap）、医药魔方、药智、Cortellis 都是订阅制商业数据库，**没有面向个人的公共 API**。智慧芽有企业开放平台，但需要合同与账号，个人拿不到 key。不在登录态下做自动抓取——违反服务条款、有封号风险，且数据不可再分发。

**决定（2026-11-03）**：本期不接入任何付费数据库，也不做人工导入通道。将来若拿到账号或合同，按同一 Item 接口新增一个适配器即可，不影响其余部分。

对你当前用途，结构化管线库的边际价值有限：它的核心价值在 BD 与投资尽调（专利族、交易条款、全量管线），而 MSL 不看专利，你要的是格局认知。

### 免费替代层（能覆盖约七成）

| 数据 | 源 | 用途 | 接入方式 |
|---|---|---|---|
| 全球临床试验 | ClinicalTrials.gov API v2 | 管线进度、读出时点、催化剂日历 | 公开 REST，免费 |
| 中国临床试验 | 药物临床试验登记与信息公示平台 | 国内在研项目与牵头单位 | 公开页面 |
| 获批与标签 | openFDA | 获批事件、说明书变更、安全性信息 | 公开 REST，免费 |
| 不良反应信号 | FDA FAERS（openFDA） | class effect 早期信号 | 公开 REST，免费 |
| 文献与指南 | PubMed E-utilities、Europe PMC | 关键研究、指南、阴性结果 | 公开 API，免费 |
| 公司公告 | 港交所披露易、沪深交易所 | BD、财报、管线变动 | 公开页面 |

这一层比抓中文媒体更重要——催化剂日历和安全性信号基本靠它撑起来。

**设计约束**

- 每个源适配器独立、可单独运行、失败不影响其他源
- 适配器只负责「取回并归一化」，不做打分
- 打分、聚类、配额集中在 `filter.py`，是唯一需要严格测试的模块
- 全流程幂等：同一天重复运行不产生重复条目

**运行环境**

| Runner | 时区 | 负责 | 原因 |
|---|---|---|---|
| GitHub Actions | UTC 11:00（= CST 19:00） | 英文 RSS、监管公告、公告文件 | 境外 IP 稳定可达 |
| 本机 launchd | CST 19:00 | 中文媒体源 | 需走 `127.0.0.1:7890`，部分站点境外 IP 受限 |

`media_cn.py` 的代理地址取环境变量 `PHARMA_RADAR_PROXY`，缺省 `http://127.0.0.1:7890`；显式设为空串时不走代理（GitHub Actions 的用法）。单个源取回失败只记日志并跳过，不中止整次运行。

两个 runner 写入同一数据目录，按 `id` 合并。GitHub Actions 的 cron 有分钟级延迟，验收标准按 19:30 计。

**日报窗口**：前一日 19:00 至当日 19:00。这个切点能同时覆盖亚洲当天与欧美隔夜消息。

**模型使用**：仅对通过规则筛选的条目做两件事——确认维度、生成 ≤40 字 `why`。每日 30–40 次小调用，使用低成本模型。规则无法判定的边界案例才交给模型，其余不调用。

## 8. 页面设计

静态站点，五屏，每屏一个职责，移动端优先（晚间手机浏览为主）。

1. **今日**
   - 顶部「必看」3–5 条大卡：当日 M≥5，或涉及指南/监管/医保且 M≥4
   - 下方当日全部条目，M 降序
   - 每条显示：维度色带、M 徽标、标题、来源、`why`
   - 目标：10 分钟读完

2. **认知地图**
   - 六格，每格显示「最近 30 天该维度最重要的一条」+「上次读到该维度距今 X 天」
   - 这一屏回答「我懂不懂这个行业」，是全站的核心

3. **领域档案**
   - 按 TA / 靶点聚合（HER2 乳腺癌、GLP-1、PD-1、ADC 等）
   - 三段结构：时间线、当前格局、未解问题
   - 用途：面试前 20 分钟快速建立领域认知

4. **催化剂日历**
   - 按日期倒排的未来事件：III 期读出时点、PDUFA 与审批截止、ASCO/ESMO/AACR/ASH/ADA/CSCO 会期、医保谈判窗口
   - 显示距今多少天

5. **全部**
   - 六维筛选 + 全文搜索 + 按月归档

**视觉约束**：沿用使用者已有的静态站习惯，纯 HTML/CSS/JS，无框架、无构建工具、无外部 CDN 依赖。六个维度各一个色相，M 用点数或徽标，不用进度条。

## 9. 分期

| 期 | 内容 | 工时 | 完成标志 |
|---|---|---|---|
| P1 | schema、2 个英文 RSS 源、NMPA/CDE 源、规则打分、配额截断、「今日」页 | 1 天 | 本机跑通一次，页面能看到当日条目 |
| P2 | ClinicalTrials.gov / openFDA / PubMed 接入、催化剂日历初版 | 0.5 天 | 日历上有真实未来事件 |
| P3 | 中文媒体源（静态可达的三个）、跨源聚类去重 | 0.5 天 | 同一事件多源报道合并为 1 条 |

P3 的 pyrecrawl 接入改为人工补抓工具，不进自动流水线（原因见 §7 的 2026-11-04 决定）。

**口径收窄（2026-11-04，P3 交付时确定）**：P3 的聚类去重只覆盖「同一期窗口内、同一语言」的多源同事件。跨窗口（同一事件在不同日期被不同源报道）、跨语言（中文稿与英文稿报道同一事件）不合并——后者需要 `title_zh` 翻译与持久化的 cluster 索引，留到 P5 与周末覆盖报告一起做。列表页只给日期、不给时刻的中文源，`published_at` 记纯日期，因此当日 19:00 之后发布的条目落到下一期，由 `id` 去重保证不重复。
| P4 | 认知地图、领域档案 | 0.5 天 | 两屏可访问 |
| P5 | GitHub Actions 与 launchd 定时、周末覆盖报告、偏科补抓 | 0.5 天 | 连续两天无人干预自动更新 |

---

## 10. 验收标准

1. 连续 14 天，每天 19:30 前「今日」页有当日更新
2. 必看条目 ≤5 条，全页 10 分钟内读完
3. 30 天内六个维度均至少出现过一条 M≥4
4. 同一事件的多源报道不重复出现（P3 口径：同一期窗口内的多源报道；跨窗口与跨语言的合并见 §9 的口径收窄）
5. 面试前 20 分钟，仅凭「领域档案」能讲清一个治疗领域的当前格局
6. 任一源抓取失败时，其余源仍能生成页面，且页面标注「本期缺 X 源」

## 11. 风险与预案

| 风险 | 预案 |
|---|---|
| 中文源抓取不稳（反爬、改版） | 降级为 RSS 镜像或手动导入；单源失败不阻断整期 |
| 模型分类漂移 | 关闭模型分类，全切关键词与实体规则 |
| 页面只收藏不读 | 压缩「必看」至 3 条；增加「上次读到本维度距今 X 天」的提醒 |
| GitHub Actions 定时延迟或不触发 | 保留本机 launchd 作为主路径，Actions 作为兜底 |
| 六维配额导致低频维度凑数 | 允许某维度空缺，但周末报告必须显式指出 |

## 12. 明确不做的事

- 不追踪股价与 K 线
- 不做个股或公司评级
- 不做预测性判断（只描述已发生与已知的将发生）
- 不做评论区、分享、订阅推送
- 不接入付费数据库（医药魔方、Insight 等）
- 不做中药以外的垂直专题（中药政策作为 D4/D3 的子项收录即可）
